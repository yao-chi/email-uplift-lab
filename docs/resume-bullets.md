## 1. 推荐版本（放在简历第一个项目位）

**邮件营销增量（Uplift）评估与预算分配** ｜ 独立完成 ｜ 2026.11
`Python` `SQL(DuckDB)` `Scikit-learn` `因果推断` `A/B 实验`

- 基于 64,000 人真实三臂随机对照实验（Hillstrom），用 SRM 卡方（p=0.90）与标准化均值差（max|SMD|=0.016）验证分组无偏后，以 Lin 式协变量调整 + HC1 稳健标准误估计增量，Holm 校正后全部显著。
- 量化结论：男装邮件使访问率 **+7.60pp**、转化率 **+0.675pp**；以客单价 116.36 元、单封成本 0.10 元建模，全量投放期望净利 **218.9 元/千封**，盈亏平衡增量 0.215%，实测为其 3.2 倍。
- 用 2×2 交互检验定位异质性：**男装女装双购客群增量 13.44pp**（其余 6.99pp，p=1.5e-06）；同时发现女装创意发给"只买男装"人群增量仅 1.11pp，证明创意—客群错配会吞掉增量。
- 构建 T/S-learner 与响应模型对比，以 **Qini/AUUC + 2,000 次 bootstrap** 评估：三模型 AUUC 较随机提升 2.1%/10.0%/15.6%，但区间均覆盖随机基线，结合功效分析（当前样本 MDE=1.63pp，检出 0.2pp 需每格 7.1 万人）判定个体级定向不可验证，改以客群规则落地。

## 4. 技能栏同步调整

现在的写法：

> SQL（MySQL）：熟悉多表 JOIN、分组聚合、条件筛选

**太弱，而且刚好是面试官最爱追问的地方。** 改成：

> **SQL**：窗口函数（`ROW_NUMBER`/`LAG`/`SUM() OVER`）、CTE、`UNPIVOT` 长宽表转换、多表关联与分群聚合；在项目中用 DuckDB 搭建口径层（`sql/01–03`），把数据清洗、分群指标与 Python 建模解耦。

> **因果推断 / 实验**：SRM 检验、协变量平衡（SMD）、Lin 式协变量调整、CUPED、Holm 多重比较校正、交互效应检验、MDE 功效测算。

> **机器学习**：T-learner / S-learner 增量建模、Qini/AUUC 评估、bootstrap 置信区间、HistGradientBoosting。

## 5. 千万不要写的

| 别写 | 为什么 |
|---|---|
| "模型准确率 95%" | 转化率只有 0.9%，95% 准确率意味着"全预测为不转化"，是负面指标 |
| "AUC 0.85，效果显著" | 本项目没报 AUC；而且 AUC 高不代表 uplift 高，被追问会崩 |
| "定向投放提升 ROI 168%" | 区间重叠，不成立；一说就假 |
| "独立完成" 单独强调 | 简历里写"独立完成"反而显得没协作经验；放在项目名后小字即可 |
| "使用 XGBoost/LightGBM 调参至最优" | 本项目的重点是"证明不能调"，写调参会自相矛盾 |
| 任何没跑过的数字 | 面试官会让你打开 `results.json` |

## 6. 面试时怎么"打开"这个项目（30 秒演示路径）

如果真的被要求"展示一下"，按这个顺序点开（都在 GitHub 上）：

1. `README.md` 顶部那张三臂对比图 → 一眼看到 10.6% / 15.1% / 18.3%
2. `README.md` 的"一句话结论"表格 → 六个结论 + 证据强度
3. `outputs/figures/03_qini_curves.png` → 三条曲线和随机线贴在一起（诚实的地方）
4. `outputs/tables/strategy_compare.csv` → 策略对比和区间
5. `reports/report.md` 第 4.3 节 → GATE 十分位，D10 符号反了

**这个顺序是设计过的**：先给结论（吸引），再给证据（可信），最后给"我没做成什么"（加分）。大部分候选人到第 2 步就没了。
